Mockingbird — Admin Guide

Everything an ADMIN can do in Mockingbird — the full user functionality (projects, uploads, deployments, reports) plus the admin-only capabilities: user management, the audit log, and permanently deleting a project.

Projects, upload, and deploy — same as any user

As an admin you have every capability described in the User Guide — creating projects, uploading specs (single file or batch, with automatic request/response pairing), generating stubs with AI, testing locally, deploying to AWS, and downloading reports. That full walkthrough with screenshots isn't repeated here; this guide focuses on what's unique to your role.

Quick links into the User Guide: Dashboard · Create a project · Batch upload & pairing · AI generation · Deploy to AWS · Reports

User management ADMIN

Open Admin in the top nav — the Users tab is the default view.

Users tabEvery account, its role, and whether it's active. Change a role directly from the dropdown in the table — no separate save step needed.

Creating a user

  1. Click New User.
  2. Fill in username, email, a temporary password, and pick a role (VIEWER / SV_TEAM / ADMIN).
  3. Click Create — the account is active immediately.
New User form
Filled in and ready to submit

Changing a role, resetting a password, suspending an account

  • Role — use the dropdown directly in the Users table row; it saves on change.
  • Reset password — click the button in that user's row to issue a new temporary password.
  • Suspend / reactivate — toggle the Active column to immediately block or restore portal access without deleting the account or its history.

Audit log ADMIN

Switch to the Audit Log tab in Admin for a timestamped record of every significant action across the platform — logins, project creation, uploads, generation, deployment, user management changes, and project deletions.

Audit logWho did what, and when — filterable, newest first.
The audit trail survives project deletion. Deleting a project cascades to its stubs, deployments, and job history — but not its audit entries. Those are preserved (with the project's name and team snapshotted into the record) specifically so deleting something doesn't also erase the accountability record of what happened to it.

Deleting a project ADMIN

Unlike Archive (which just hides a project from the dashboard, fully reversible, available to SV_TEAM too), Delete is a permanent, admin-only action available directly from the dashboard.

  1. On the dashboard, hover a project card — a delete (trash) icon appears top-right. In list view, it's the last column.
  2. Click it, and review the confirmation dialog carefully.
  3. Click Delete permanently to confirm.
Confirmation dialogStates plainly what gets deleted and that it can't be undone.
What actually happens: the project, all its stubs, deployments, and job history are permanently removed from the database. This does not automatically suspend a currently-live AWS deployment first — if the project has a live stub, suspend it before deleting, or you'll orphan a running (billable) EC2 instance with nothing left in the portal to manage it.
Who can delete: ADMIN role only, enforced by the backend regardless of what the UI shows — an SV_TEAM user has no delete option on the dashboard at all.
