Mockingbird Setup Guide: Company Machine, Node 24

Follow these steps to move a new copy of the Mockingbird code onto your company Windows machine, build it, and run the portal and its services. The steps assume you are upgrading from an older copy that ran on Node 20 or 22. They work just as well for a first install: skip the parts marked (upgrade only).

All company-specific values are placeholders. Wherever you see <ARTIFACTORY_NPM_URL>, <ARTIFACTORY_PYPI_URL> or <CORP_CA_BUNDLE>, substitute your own values on your machine. Never write them back into the repository, because it is public.

The short version

  1. Stop the old services and rename the old folder to keep it as a backup.
  2. Make sure node -v shows v24.x in a new terminal.
  3. Put the new code in C:\Workspace\Mockingbird. Copy across four data items from the old folder (§5).
  4. Run .\setup.ps1. It installs, upgrades and checks everything, and stops with a clear message if something is wrong.
  5. Run .\start-dev.ps1, then open http://localhost:3010.

1. Why a plain copy fails after the Node 24 upgrade

Copying the new code over the old folder and starting it usually breaks in one of these ways. setup.ps1 now handles every one of them, so you only need this table if you want to know what it is doing.

What changedWhat breaks if you only copy filesHow it's handled
Node.js 24 is now required ("engines": ">=24" in all three Node projects)Old node_modules contain the native module better-sqlite3, compiled for Node 20/22 (bcrypt 6 uses a version-independent binary and is unaffected). auth-service crashes at start with NODE_MODULE_VERSION 127 … requires 137, and the portal login then shows ECONNREFUSED.setup.ps1 checks Node ≥ 24, runs npm install and npm rebuild, then loads each native module to prove it works.
New Python dependency: openpyxl (xlsx stub template)An existing venv doesn't have it, so an xlsx upload fails with MB-SYS-002 · Server is missing the 'openpyxl' component.setup.ps1 now installs each service with its dependencies, then checks that the xlsx parser imports.
New database migrations (per-stub protocol/TLS columns)The old mockingbird.db lacks the new columns, giving no such column: stubs.protocol and "Failed to load projects".setup.ps1 backs up the database, then upgrades it with alembic upgrade head. Your projects and stubs are kept.
.env files are not in gitA fresh copy has none, so services start with no JWT secret. Everything returns 401, or auth refuses to start.setup.ps1 creates any missing file with one shared secret, and fixes an ingestion database path copied from another folder.
Ports changed: auth-service 3002, portal 3010Old bookmarks and scripts still use 3001 and 3000.Use start-dev.ps1 and http://localhost:3010.

2. Prerequisites checklist

Open a new PowerShell window after installing anything, because PATH changes only reach new windows. Then check each line:

ToolCheck commandMust showNeeded for
Node.js 24 (npm comes with it)node -v · npm -vv24.x.x · 10.x or newerportal, auth-service

Several Node versions installed? where.exe node lists every node.exe on your PATH, and the first one wins. If it isn't Node 24, fix PATH or uninstall the old one. With nvm-windows, run nvm use 24.

3. Company network: npm and pip registries, certificates

Do this once per machine. Check first, because it may already be configured from your old install:

npm config get registry
python -m pip config list

If npm doesn't point at your Artifactory, or pip shows no index-url, set them:

npm config set registry <ARTIFACTORY_NPM_URL>
python -m pip config --user set global.index-url <ARTIFACTORY_PYPI_URL>

:: Only if you get SSL / "self-signed certificate in chain" errors:
npm config set cafile <CORP_CA_BUNDLE>
python -m pip config --user set global.cert <CORP_CA_BUNDLE>

Native modules (better-sqlite3, bcrypt)

These two modules contain compiled code for your exact Node version.

  • bcrypt ships its Windows binary inside the npm package, so there's nothing extra to download.
  • better-sqlite3 downloads a matching prebuilt binary from GitHub during npm install. If your proxy blocks GitHub, it falls back to compiling locally. That needs Visual Studio Build Tools with the “Desktop development with C++” workload, plus Python (which you already have).

You'll know which case you're in because setup.ps1 stops with “Native module 'better-sqlite3' does not load”. When that happens, either:

  • ask IT to install Visual Studio Build Tools (C++ workload), then delete services\auth-service\node_modules and re-run .\setup.ps1, or
  • ask whether Artifactory proxies GitHub release downloads. If it does, point the prebuilt download at that mirror before running setup. The variable is read by better-sqlite3's installer; check the exact URL format with whoever runs Artifactory.
$env:npm_config_better_sqlite3_binary_host = "<ARTIFACTORY_GITHUB_RELEASES_MIRROR>"

4. Stop and back up the old install (upgrade only)

  1. Close the four service windows of the old install, or press Ctrl+C in each.
  2. Make sure nothing is still holding the ports. This must print nothing: 
    Get-NetTCPConnection -State Listen -LocalPort 3001,3002,3010,8001,8003 -ErrorAction SilentlyContinue
    If it prints something, stop that process: Stop-Process -Id <OwningProcess>.
  3. Rename the old folder so it becomes your backup: 
    Rename-Item C:\Workspace\Mockingbird Mockingbird-old
Why a new folder instead of copying over the old one? Python virtual environments (venv) remember the absolute path they were created in, and old node_modules carry Node 22 binaries. A clean folder avoids both problems, and the old one stays untouched if you need to go back.

5. Put the new code in place and bring your data across

1Get the code into C:\Workspace\Mockingbird

Use whichever way you normally get code onto the machine: git clone, git pull into a fresh clone, or unzipping a copy. Do not copy these from anywhere, because setup.ps1 creates them fresh:

  • venv folders (in each services\* folder)
  • node_modules folders (in portal and services\auth-service)
  • services\auth-service\dist

2Copy your data from the old folder (upgrade only)

These four items hold your users, projects, stubs and uploaded files. Copy them from Mockingbird-old into the same place in the new folder:

ItemContainsIf you skip it
services\project-service\mockingbird.dbprojects, stubs, jobsThe portal starts empty.
services\ingestion-service\uploads\ (whole folder)uploaded spec files and generated stub projectsExisting stubs are listed, but Download Stub Project returns 404 until you re-upload.
services\auth-service\auth-local.db (and any auth-local.db-* next to it)user accountsYou have to create users again (§8).
The three .env files: services\auth-service\.env.local, services\project-service\.env, services\ingestion-service\.envJWT secret and pathsNothing bad: setup.ps1 creates new ones.
$old = "C:\Workspace\Mockingbird-old"; $new = "C:\Workspace\Mockingbird"
Copy-Item "$old\services\project-service\mockingbird.db" "$new\services\project-service\"
Copy-Item "$old\services\ingestion-service\uploads" "$new\services\ingestion-service\" -Recurse
Copy-Item "$old\services\auth-service\auth-local.db*" "$new\services\auth-service\"
Copy-Item "$old\services\auth-service\.env.local" "$new\services\auth-service\"
Copy-Item "$old\services\project-service\.env" "$new\services\project-service\"
Copy-Item "$old\services\ingestion-service\.env" "$new\services\ingestion-service\"

Your sample and client files (Sample_SV_Files) are never part of the repository, so copy that folder too if you keep it inside the project.

6. Run setup.ps1

cd C:\Workspace\Mockingbird
.\setup.ps1

The first run downloads every package and usually takes 3 to 10 minutes, depending on your network. Every step prints [OK], [SKIP] (already done) or [NOTE] (something it fixed for you). The lines that matter:

You should seeMeaning
[OK] Node.js : v24.x.xThe right Node is on PATH.
[OK] existing JWT secret reused or new JWT secret generatedThe .env files are consistent.
[NOTE] ingestion-service\.env database_url pointed at … correctedNormal after copying .env from the old folder. It now points at this folder's database.
[OK] backed up existing database to mockingbird.db.bak-…
[OK] database upgraded to the latest version (projects and stubs kept)		Your old database was migrated. The backup sits next to it.
[OK] xlsx parser importableopenpyxl is installed; xlsx uploads will work.

If it stops with [ERROR], the message says what to do. The common ones are in §10. Fix the problem and re-run .\setup.ps1; it's safe to run any number of times.

7. Start the services and check they are healthy

cd C:\Workspace\Mockingbird
.\start-dev.ps1

Four windows open, one per service. Leave them open. After about 20 seconds (auth-service compiles TypeScript first), check each one in a new PowerShell window:

curl.exe http://localhost:3002/health    # auth-service
curl.exe http://localhost:8001/health    # project-service
curl.exe http://localhost:8003/health    # ingestion-service
curl.exe -s -o NUL -w "%{http_code}" http://localhost:3010/   # portal - prints 200

The first three each print JSON containing "status":"ok". If one doesn't respond, look at that service's window: the error is printed there.

8. First login and a quick smoke test

Users

If you copied auth-local.db, log in with your existing accounts. On a fresh install, create the two default accounts once, while the services are running:

.\scripts\seed-users.ps1

This creates sv.admin (ADMIN) and sv.user (SV_TEAM). The initial passwords are in the script; change them on the Admin page afterwards.

Smoke test (2 minutes)

  1. Open http://localhost:3010 and log in. The Projects dashboard lists your existing projects (upgrade) or is empty (fresh).
  2. Open a project and check its stubs are listed with no "Failed to load" message.
  3. Click Upload Spec, pick an empty .txt file and click Upload & Generate. You should see the red line MB-UPL-001 · '<name>.txt' is empty. That proves the portal → ingestion → parser chain and the new error messages work end to end.
  4. Upload a real spec as usual. It should reach DONE and Download Stub Project should download a zip.

Validating the generated stubs and NFT scripts against your real files is a separate step, done with your own data.

9. Stopping everything

Close the four service windows, or press Ctrl+C in each. To check nothing is left running:

Get-NetTCPConnection -State Listen -LocalPort 3002,3010,8001,8003 -ErrorAction SilentlyContinue

Appendix A: what setup.ps1 does (manual equivalent)

Use these commands only if you can't run the script. Run them in order, from C:\Workspace\Mockingbird:

# 1. .env files (see section 5) - all three JWT secrets identical, no trailing spaces
#    services\auth-service\.env.local : JWT_SECRET=<secret>
#    services\project-service\.env    : database_url=sqlite:///./mockingbird.db
#                                        jwt_secret=<secret>
#                                        local_storage_path=./uploads
#    services\ingestion-service\.env  : database_url=sqlite:///C:/Workspace/Mockingbird/services/project-service/mockingbird.db
#                                        jwt_secret=<secret>
#                                        local_storage_path=./uploads

# 2. parser-worker
cd services\parser-worker
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe -m pip install -e .

# 3. project-service + database (back up mockingbird.db first if it exists)
cd ..\project-service
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe -m pip install -e .
$env:DATABASE_URL = "sqlite:///./mockingbird.db"
.\venv\Scripts\python.exe -m alembic upgrade head
Remove-Item Env:DATABASE_URL

# 4. ingestion-service (parser-worker first)
cd ..\ingestion-service
python -m venv venv
.\venv\Scripts\python.exe -m pip install -e ..\parser-worker
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe -m pip install -e .
.\venv\Scripts\python.exe -c "import openpyxl, parser_worker.detector"   # must print nothing

# 5. auth-service + portal (Node 24)
cd ..\auth-service
npm install
npm rebuild
node -e "require('better-sqlite3'); require('bcrypt')"                  # must print nothing
cd ..\..\portal
npm install

Appendix B: running the automated tests (optional)

These are useful to confirm the copy is healthy on your machine. None of them need company data.

# Python services (from each service folder)
cd services\parser-worker;    .\venv\Scripts\python.exe -m pytest -q
cd ..\ingestion-service;      .\venv\Scripts\python.exe -m pytest -q
cd ..\project-service;        .\venv\Scripts\python.exe -m pytest -q

# auth-service
cd ..\auth-service;           npm test

# portal unit tests
cd ..\..\portal;              npx vitest run

# portal end-to-end, against the RUNNING services (start-dev.ps1 first; needs sv.admin / sv.user)
npx playwright install chromium        # first time only
npx playwright test --config=playwright.real.config.ts

Tests that read real capture files from Sample_SV_Files are skipped automatically when those files aren't present.
